# Keyboard Shortcuts

Every project shortcut comes from one action table, `HammerActions` in
`common/.../components/actions/HammerActions.kt`. The F1 cheat sheet and the `Mod+K` command
palette list the same table, and menus and format bar tooltips show its chords.

## Chord rules

- **Mod** is `Cmd` on macOS and iOS, `Ctrl` on Windows, Linux and Android. The other key held
  means no chord: on a Mac `Ctrl+N` stays Cocoa's caret move, not New.
- Modifiers match exactly: an extra modifier means no chord, so `Ctrl+F3` does not sync.
- No chord uses `Alt`. Windows reports `AltGr` as `Ctrl+Alt`, so an `Alt` or loosely matched
  chord would fire while a Polish, German or Turkish layout types a character (issue #859).
- Letters match the layout's letter (`layoutKey`), so chords stay on their letter on AZERTY,
  Dvorak and the like. Digits match the digit row and the NumPad.

## Hosts

Table chords are matched before Compose focus, so they work with nothing focused. The host
turns the key into a `KeyChord` and calls `ActionRegistry.dispatch`; a chord nothing handles
passes on to the focused widget.

| Platform | Host                                                                         |
|----------|------------------------------------------------------------------------------|
| Desktop  | `ProjectEditorWindow.kt` window `onPreviewKeyEvent`                          |
| Android  | `ProjectRootActivity.dispatchKeyEvent` via `androidChord`                    |
| iOS      | `UIKeyCommand`s generated by `iosKeyCommands(keymap)`, in `ComposeContainer.swift` |

Handlers register by layer (`Root`, `Module`, `Item`, `Overlay`); the highest live layer wins.
An open dialog or menu is an overlay that blocks everything below it except global actions.

| Action               | Chord                        | Does                               |
|----------------------|------------------------------|------------------------------------|
| `edit.save`          | `Mod+S`                      | Save the open item                 |
| `edit.find`          | `Mod+F`                      | Find bar (scene editor, focus mode)|

| `edit.italic`        | `Mod+I`                      | Italic                             |

## Panes, tree and lists

`F6` and `Shift+F6` move between a screen's panes (the scene tree and the editor, or a list
and the item open from it) and return to the control each pane last had focused. Moving to a
new module with a keyboard focuses its first pane.

The scene tree and the note and entry grids are one focus stop each, with a cursor drawn as a
hairline frame while they have focus. Clicking a row puts the cursor there and focuses the list.

| Key           | Scene tree                                       | Note and entry grids    |
|---------------|--------------------------------------------------|-------------------------|
| `Up`, `Down`  | Previous or next row                             | Row above or below      |
| `Left`        | Collapse a group, else go to the parent group    | Previous item           |
| `Right`       | Expand a group, else go to its first child       | Next item               |
| `Home`, `End` | First or last row                                | First or last item      |
| `Enter`       | Open a scene, or open or close a group           | Open the item           |

The tree's cursor starts on the open scene when the tree takes focus.

## Esc

Esc is not in the table. It steps out one level at a time:

1. In the scene editor beside the tree, Esc moves focus to the tree with the cursor on the open
   scene, expanding its groups; the scene stays open. In the scene editor on a narrow window,
   and in an open note, entry or event, Esc leaves the text field and keeps editing.
2. The next Esc closes the item, as back does. The tree or list keeps or regains focus with its
   cursor on the item just closed.
3. Further Esc presses go back as before, up to Home.

To leave the scene editor for the next pane, press `F6`: after Esc, focus is in the tree, so
Tab moves on from there.

In a new note, entry or event, the first Esc is taken and does nothing else, and the second in a
row goes back (asking first if anything is filled in). Tab indents in a rich text body, so to
move on from the body press Esc then Tab, or `Ctrl+Tab`. `Mod+Enter` creates the item from any
field.

A control focused from the keyboard draws an ink frame just inside its border.

An Esc that closes a dialog, menu, find bar or popup does only that, and never also goes back.

On Android and iOS, system back is unchanged.

For developers: `EscapeRouter` handles Esc for both desktop windows, and `escapeToPane`
(`EscapeToPane.kt`) takes the first step inside a pane.

## Adding an action

1. Add an `ActionDef` to `HammerActions` with its default chords, and its label to
   `strings_actions.xml`.
2. Register a handler where the action can be done: `registerWhileStarted` in a component, or
   `RegisterActions` in Compose for focus and host actions.
3. Add a row to this file. `KeyboardShortcutsDocTest` fails while any action id is missing.
   `ReservedChordsTest` fails on a chord that collides with the text editor's or another action's.
